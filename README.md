# midterm_project
新一线城市CityWalk空间适宜性与多源数据分析

 

## 1. 项目简介

本项目以15个新一线城市为研究对象，结合OpenStreetMap（OSM）步行道路网络、高德地图POI数据和遥感绿化数据，从步行路网、商业设施、公共交通接驳和绿化条件等方面，分析不同城市的CityWalk空间适宜性。

项目主要使用Python、QGIS及Google Earth Engine（GEE）等工具，完成数据采集、清洗、空间匹配、指标计算和可视化分析。

### 3.2 商业设施分析
基于已构建的15个城市、300个CityWalk目的地空间样本，调用高德地图API获取其周边500米辐射范围内的商业服务点数据。在数据处理阶段，对包含复合标签的商业POI记录进行了字段拆分与重构，确保每一条数据仅对应单一的底层细分业态。

在空间测算环节，依托各景点中心坐标生成500米缓冲区，利用空间距离计算统计落入区内的商业设施总数，从而量化商业服务供给的密集程度。此外，提取高德三级分类字段，利用香农-威纳指数测算各目的地周边的业态多样性，以刻画商业功能的混合特征。

通过叠加分析上述指标，探讨不同城市在商业资源总量与业态结构均衡度上的空间分异。
### 3.3 公共交通步行接驳分析

通过高德地图Web API采集15个城市的CityWalk候选目的地及其周边800米范围内的地铁出入口和公交站点数据。经过数据清洗、坐标转换、AOI范围筛选、名称去重和评分排序，每个城市选取20个CityWalk目的地，共300个研究样本。

结合OSM步行道路网络，利用QGIS、PyQGIS及Dijkstra最短路径算法，计算景点与周边地铁、公交站点之间的最短估算步行距离。

计算过程中，通过空间索引查找附近道路，每个位置最多设置3个道路接入点，并将景点接入距离、OSM道路最短路径距离和站点接入距离相加，得到估算总步行距离。对于无法获得有效路径的景点，单独记录失败状态，不使用直线距离代替步行距离。

同时，结合景点周边500米范围内的商业POI数量，开展交通与商业配套分析，通过四象限散点图及交通—商业双优景点占比，比较不同城市的交通接驳与商业服务条件。

### 3.4 绿化与综合适宜性分析
基于多源数据清洗与空间匹配后的融合数据集，本研究构建了包含“步行连通性、商业服务、交通接驳与绿化条件”四个维度的CityWalk综合适宜性评价体系。

在绿化环境测算方面，通过Google Earth Engine (GEE)平台调用Sentinel-2遥感影像，经云掩膜处理后计算归一化植被指数（NDVI），并以30m分辨率聚合至500m网格，量化各目的地的自然生态基底。

在综合评价环节，首先采用Z-score标准化方法消除各指标的量纲差异。随后，为了探究不同游逛偏好对结果的影响，设定了基准（等权重）、自然偏好（重绿化）与购物偏好（重商业）三种差异化的权重情景进行敏感性分析。最后，利用K-Means无监督聚类算法对所有城市网格进行空间分异识别，通过聚类中心的雷达图特征，揭示了城市内部显著的“空间权衡（Spatial Trade-off）”现象。

## 5. 代码运行说明

项目代码按照数据处理流程分为四个主要目录：

1. `crawler/`：数据采集。
2. `processing/`：数据清洗、坐标转换与空间匹配。
3. `analysis/`：道路网络分析、最短路径计算与指标统计。
4. `visualization/`：研究图表与可视化结果生成。

运行前需配置相应Python依赖及数据路径。涉及QGIS和PyQGIS的代码需要在相应GIS环境中运行。

详细运行步骤及参数参见 `docs/` 中的研究方法说明。

## 6. 研究说明

本项目整合不同来源的空间数据开展城市间比较。由于数据采集时间、空间精度和覆盖范围存在差异，研究结果可能受到数据完整性及空间匹配误差的影响。

其中，公共交通接驳距离为基于OSM道路网络的估算值，不完全等同于实际导航距离。

项目相关数据和代码的公开使用应遵守原始数据来源的许可要求。
